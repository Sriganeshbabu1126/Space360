SPACE360
Revised Application Development Roadmap
SGB Dev Apps  ·  Ganesh Hari  ·  August 2026
Version 2.0  —  Supersedes original 5-phase roadmap
⚠️  Critical Architecture Change
The 360° camera does not take single photos — it captures 
continuous video at 2 frames per second
 while the operator walks. This changes the data model across all modules. A "capture session" is a walk containing many timestamped frames — not a single image tied to one location point.
1. What Changed & Why
This revision keeps every technical decision already made and adds three things:
• 
A priority order — MVP first (Stages 1–2), then Stages 3–5 — so the team knows build sequence without dropping anything.
• 
A corrected capture spec — continuous 2 fps video, not single photos. This changes how Modules 1–3 are built.
• 
A staged activation rule — architectural upgrades activate only after major milestones, not mid-build.

STAGE 2 — 
Data Model Upgrade (2fps Architecture)
Priority: P0 Critical   |   Sprint: After Stage 1
Goal
Upgrade the session data model to support frame sequences, not single images.
Activate when
Stage 1 complete — all prototype features working end-to-end.
Frame Sequence
Add frame_index, captured_at, gps_lat, gps_lng fields to sessions table via Alembic.
Session Model
Site → Location Point → Capture Session (dated) → Frame Sequence (2fps frames).
Nearest Frame
Logic to select closest frame to a location point GPS anchor across sessions.
API Update
Update all session endpoints to support frame-level queries.
Success
A session holds an ordered frame sequence; nearest-frame lookup works by GPS anchor.
STAGE 3 — 
Mobile App (React Native)
Priority: P1 High   |   Sprint: After Stage 2
Goal
Field operator can capture 2fps 360° video from phone, auto-upload to GCS with GPS metadata.
Activate when
Stage 2 data model is stable and tested.
Camera SDK
Insta360 SDK (primary) or LG R105 OSC API (current hardware) — 2fps walk capture.
GPS Tagging
Per-frame GPS + timestamp + location label attached during walk.
Upload
Auto-upload frame sequence to GCS; offline queue for poor connectivity.
Mobile UI
React Native capture screen — pair camera, trigger walk, confirm upload.
Success
Walk lands in GCS as complete 2fps frame sequence with GPS/timestamp/label per frame.
STAGE 4 — 
Production Hardening
Priority: P1 High   |   Sprint: Parallel with Stage 3
Goal
Move from local dev to production-grade cloud deployment.
Activate when
Stage 2 complete.
GCS Full
All media in GCS (360-field-check-media, asia-southeast1). Remove local fallback.

Firebase Claims
Custom claims for roles: admin, ai_pro, field_operator.
Firestore
Frame-level metadata in Firestore; relational session data stays in Cloud SQL.

App runs fully on GCP; no localhost dependencies; roles enforced via Firebase.
